# Fichas de referencia

Una referencia se estudia; no se copia. Cada ficha responde a tres preguntas: **qué aporta**, **qué recurso concreto se puede extraer** y **qué no se toma**. Así el director sabe sacar un principio (cómo coloca un titular, cómo usa el flash, cómo combina dos letras) sin entender que debe calcar la pieza entera.

## Qué se analiza de una referencia

- composición;
- jerarquía;
- relación entre foto y tipografía;
- escala;
- contraste;
- dirección fotográfica;
- tratamiento cromático;
- texturas;
- recursos gráficos;
- ritmo;
- densidad;
- personalidad.

No todo aplica siempre: se apunta lo que la referencia hace de verdad.

## Formato de una ficha

```markdown
---
nombre: <slug>
resumen: <qué es, en una línea>
fases: concepto, composicion
formatos: post, carrusel
---
# <Título> (<autor>, <año>)
Qué es · Qué aporta · Recurso que se extrae · Qué no se toma · Dónde lo hemos usado
```

## Reglas

- Solo referencias públicas y documentadas, con su autor y su año. No se suben a git imágenes de terceros: la ficha describe y enlaza.
- Las miniaturas de `biblioteca/referencias/` son posts que eligió el usuario (casi todos plantillas de diseño). Se usan para aprender oficio, no marcas ni textos.
- Una referencia no convierte su recurso en regla. Si un recurso funciona en varias piezas, se apunta como observación (`../observaciones/`).
